🚨 Breaches & Active Threats
Critical

Self-propagating "ChainDrop" npm worm poisons hundreds of packages, plants Claude Code and VS Code hooks

📅 Aug 4, 2026

A credential-stealing worm that first appeared in keyv@6.0.0 spread across the Keyv and Cacheable namespaces into hundreds of packages spanning nine-plus organizations on August 4 — passing through the project's legitimate GitHub Actions release workflow with valid OIDC/SLSA provenance intact. SafeDep verified 353 poisoned versions across 79 package names harvesting GitHub, npm, cloud, Vault and private-key material, including credential stores for Claude, OpenAI, Codex, Cursor and Gemini, and found the repository retained a Claude Code SessionStart hook and a VS Code folder-open task that can re-run the payload just by opening the checked-out project.

Why it matters: A verified, provenance-signed release still carried a worm — attestation confirms the build pipeline, not the safety of what entered it. Treat any workstation or CI runner that resolved an affected version as credential-exposed, and remove the malware's revocation-watcher before rotating tokens, not after.

Notable

CISA flags actively exploited Langflow, Apache Tomcat and N-able N-central flaws

📅 Aug 5, 2026

CISA added three vulnerabilities to its KEV catalog: CVE-2026-9198 (CVSS 9.8), an unauthenticated code-injection RCE in IBM's Langflow AI platform; CVE-2026-34486 (CVSS 7.5) in Apache Tomcat, bypassing cluster message encryption; and CVE-2026-18556, an N-able N-central auth bypass whose incomplete fix required a second patch. Unit 42 ties the Tomcat exploitation to knaithe/KnYuan, a Chinese-speaking actor running DeepSeek through the Hermes Agent framework to autonomously scope and attempt exploitation against 460+ internet-facing targets.

Why it matters: Federal agencies have until August 7 to patch, but the durable takeaway is the Tomcat CVE: an AI agent conserving its own compute budget to prioritize targets is now operational tradecraft, not a research demo — expect autonomous scanning against public-facing services to keep showing up in KEV.

15 TP-Link Omada zero-touch-provisioning flaws chain into full network takeover

📅 Aug 4, 2026

Forescout's Vedere Labs disclosed 15 vulnerabilities in TP-Link's Omada zero-touch-provisioning system, including hardcoded cryptographic keys, weak certificate validation enabling man-in-the-middle attacks, a cloud-adoption race condition and an XSS flaw in the controller web interface; some of the same weaknesses extend to TP-Link's VIGI cameras, Festa routers and Tapo/Kasa smart-home lines. TP-Link has patched a portion of the issues but says full remediation won't land until later in 2026, and some low-severity issues won't be patched at all.

Why it matters: ZTP auto-configures fleets of devices with zero manual intervention, so a chained ZTP flaw doesn't compromise one device — it compromises the whole managed fleet at once. Segment Omada controller management traffic now rather than waiting for the full patch cycle.

Over 24,650 internet-exposed server BMCs leak password hashes via 13-year-old flaw

📅 Aug 4, 2026

Security firm Lava found nearly 37,000 internet-accessible IPMI/BMC management interfaces, of which 24,650 disclose password-derived authentication hashes before any login attempt due to CVE-2013-4786 in the IPMI 2.0 protocol. More than 30% of the recovered hashes cracked easily against common wordlists and predictable factory chassis-sticker password formats, and a compromised BMC — one of the most privileged control points in a data center — can pivot to the broader management plane.

Why it matters: BMCs work even when the host OS is down, which is what makes a cracked one so dangerous. Inventory every internet-reachable IPMI interface and put it behind a VPN or jump host regardless of patch status — this flaw has no real fix beyond disabling the legacy authentication mode.

🤖 AI Security
Critical

Google deletes 3 ADK workflows after researchers pull off first agent-on-agent privilege escalation

📅 Aug 4, 2026

Pillar Security showed that a public GitHub issue on Google's Agent Development Kit for Python repo could prompt-inject a low-privileged public triage agent into posting a command that a separate, privileged code-fixing agent trusted — because the gate checked who posted the comment (a trusted bot account), not whether an outsider had manipulated that account into posting it. The researchers demonstrated arbitrary code execution on the CI runner and exfiltration of the bot's access token and a Google Cloud service-account credential; Google fixed the issue by deleting all three workflows, confirmed July 21.

Why it matters: This is the first documented case of one AI agent compromising another via inherited trust rather than a model jailbreak — if your repo automation grants a "trusted bot" identity elevated privileges, audit whether anything untrusted can make that bot say what an attacker wants.
Source
Notable

AI notetaker tl;dv exposes 180,000+ government and corporate video calls via Firebase misconfiguration

📅 Aug 4, 2026

Researcher BobDaHacker found that any user of tl;dv — an AI meeting assistant used by Salesforce, Forbes, Cloudflare and dozens of government agencies — could query the company's Google Firebase backend for every live conference call the bot was invited to, then join roughly 80% of them by impersonating the notetaker. Deeper access exposed more than 180,000 completed call records from 23 countries' governments, and a sample of 27,000 meeting IDs found over 1,000 with transcripts and invitee emails publicly exposed. The flaw remained live at time of publication; tl;dv did not respond to requests for comment.

Why it matters: An AI notetaker is a silent participant with microphone, transcript and calendar access in every meeting it joins — treat any bot in your call list as a data-handling vendor requiring the same scrutiny as SaaS with API access, and default every notetaker's sharing settings to private.
